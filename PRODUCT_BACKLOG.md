# Boss-O-Rater product backlog

Feedback from the review, with the decisions used to ship this pass. Items marked done are in the app now. Open items are waiting on a decision or on parameters that were not provided.

## Decisions made so the work could ship

- **Color.** The interface blue (`#2B5FE0`) is replaced by the logo navy (`#1B2B4A`) for brand surfaces and a burnt amber (`#C4621A`) for actions. The wordmark stays readable on a warm off-white splash instead of a solid blue screen.
- **Landing length.** The three-slide intro is one screen with a single Get started. Category choice stays on the existing privacy screen, so it does not add a page.
- **Logo.** Crown marks are replaced with `frontend/assets/boss-rater-logo.png`.
- **Email.** The field says “Email”. A normal email format is required. A work domain is not.
- **Roles.** Boss, peer, skip-level, report, and stakeholder are not collected. Relationship stays in the database for older rows and defaults to `OTHER`.
- **Profiles.** The profile is an insights-only survey. It collects country, location, state, postal code, age group, gender (M / F / Other / Prefer not to say), industry, ethnicity, and education, for the signed-in user and optionally for the person being rated. A disclaimer says the answers are used only to generate compatibility insights and are not shared. Skip leaves the survey without saving. Send stores it on that person’s private account. Compatibility comes from the scorecard ratings, not from these answers.
- **Sharing.** Subject and body are system-written. The subject is `Someone rated you on boss-o-rater.` Senders cannot edit the copy.
- **Secure feedback.** The email contains an unguessable link. Opening it asks for the recipient’s email, then a one-time code sent only to that inbox. Scores are not in the email itself.
- **Social.** The share sheet shows a scorecard card meant to be screenshotted for Facebook, Instagram, or LinkedIn. Posting into those networks is not wired up.

## Still open

- Authenticate the sending domain. Add the Resend SPF and DKIM records in GoDaddy, then a DMARC record, so scorecard and password mail is not treated as spam. The live From address is on `noreply.bossorater.com`, which Resend already shows as verified. `bossorater.com` itself is not verified, and its existing Outlook SPF must be kept when new records are added.
- Verify the root domain bossorater.com in Resend and GoDaddy so mail can send from `noreply@bossorater.com`. The API key is already on Cloud Run. The verified domain today is `noreply.bossorater.com`, which cannot send as the root address.
- After the iOS and Android apps are listed, include a scorecard summary image in the email with App Store and Play Store download badges.
- Put a traffic shield in front of the Cloud Run API if spikes should be absorbed there as well as on Firebase Hosting.
